# Persistent Multi-Repo Dev Queue Orchestrator (`agy-dev-queue-orchestrator`)

Coordinates multiple pending engineering tasks across managed repositories without per-repo lock collisions—serializing edits within the same repository while allowing distinct unlocked repositories to progress in parallel.

## Persistent Queue Commands (`dev_queue.json` · `0600` + `file_lock`)
All operations run deterministically via [`pr_remediator.py`]($HOME/.gemini/config/plugins/agy-dev-plugin/skills/agy-code-remediation-pr/scripts/pr_remediator.py):
- **Inspect queue & active repo locks**: `pr_remediator.py lock-status --all --sync-git [--summary | --format compact|md|json]`, `pr_remediator.py queue-list [--active-only] [--repo SLUG] [--limit N] [--summary | --format compact|md|json]`, and 0-LLM `pr_remediator.py queue-plan [--repo SLUG] [--importance TIER] [--include-done N] --json` (`Repo -> Sub-Component`, `Importance x Wave`, `Recently Integrated`)
- **Enqueue / update item**: `pr_remediator.py queue-add --id <CID> --title "..." --priority <10-90> [--importance critical|high|medium|low] [--component <SUBCOMPONENT>] --repos <repo1> <repo2> --status pending --target-files <f1> <f2> --depends-on <dep_cid> --rca-summary "..." --proposed-fix "..." --orchestrator-id <ORCH_CID>` (`--depends-on` merges; `--replace-depends-on <deps...>` replaces; `--clear-depends-on` empties)
- **Locked-Repo Auto-Enqueue Policy (Zero Confirmation Prompt)**: When a **Design Contract** converges (or an approved task is ready) and any target repo holds an active `dev_pr_lock`, **DO NOT ask the user for confirmation or priority**. Immediately inspect `dev_queue.json`, active `dev_pr_locks`, application architecture, dependencies (`depends_on`), and user urgency to assign a calibrated numeric priority, run `pr_remediator.py queue-add --status pending` (with `rca_summary`, `proposed_fix`, `target_files`, `depends_on`, and `repo_slugs` via `--repos`), and render a concise visual confirmation (compact Markdown table: queue position, calibrated priority, target repo(s), active blocker lock, next-up sequence).
- **Pick next unblocked items per repo (contract-first, N-slot lookahead, transitive priority inheritance, 50% WIP-finish boost & partial-WIP cap)**: `pr_remediator.py queue-next --unlocked --orchestrator-id <ORCH_CID>` returns `next_unlocked_item` (`dispatch_repos` / `partial_multi_repo_dispatch` / `target_slot`), `multi_slot_candidates` + legacy `slot2_candidates` (tasks `NONE`/`TRANSITIVE` vs ALL active slots, eligible for the next free Slot #2..#N via `start-remediation --allow-slot2`; `max_slots` 1..4, default 3), plus `runnable_by_repo` mapping every FREE repo to its highest-priority runnable task—computing cycle-safe transitive `effective_priority` (`inherited_priority_from` while preserving raw `priority`), subtracting `merged_repos`, boosting partially-merged items (`merged_repos` non-empty) ahead of 0% items on the same repo when `AGY_DEV_PRIORITIZE_PARTIAL_WIP=1` (default) while strictly preserving `P<=17` infrastructure precedence, and gating new 0% `partial_multi_repo_dispatch` when any downstream locked repo already has `>= AGY_DEV_MAX_PARTIAL_WIP` (`3` default) half-merged items waiting (keeping single-repo tasks and existing partial WIP unrestricted)
- **4-tier blast-radius overlap, speculative pre-rebase, Release Train bundling & post-merge follower rebase**: `pr_remediator.py analyze-overlap --repo <owner/repo> --workdir <DIR>` classifies candidate overlap (`NONE`/`TRANSITIVE` -> `--allow-slot2` + **Stacked Branches** `git rebase --onto` for `TRANSITIVE`; `INTERFACE_SHARED` -> Antigravity-native swarm `workspace='share'`; `DEEP_SHARED` -> serialized execution with pipelined read-only `agy-dev-planner` pre-anchoring and isolated per-feature test files `tests/test_<component>_<cid8>.py`); `pr_remediator.py speculative-rebase --repo <owner/repo>` pre-rebases ready followers over frozen Slot #1 `HEAD`; `pr_remediator.py bundle-ready-slots --repo <owner/repo> [--publish]` combines 2–3 `PASS > 90` disjoint `READY_AWAITING_BASE_MERGE` slots into one verified Release Train PR (`test-local --mode ci-parity` + atomic rollback); `pr_remediator.py rebase-reverify --repo <owner/repo> --workdir <WORKTREE_PATH> --fetch` promotes followers onto updated `origin/main` (`AUTO_PROMOTED_ZERO_LLM` / `NEEDS_AGENT_SEMANTIC_FIX` / `NEEDS_AGENT_CONFLICT_RESOLUTION`)
- **0-LLM reactive auto-wakeup waiter**: `pr_remediator.py wait-for-unlock --orchestrator-id <ORCH_CID> --interval 15 --max-duration 3600 [--stall-seconds 900]` (polls `sync_dev_pr_lock_with_git()` with 0 LLM tokens and exits cleanly on `repo_unlocked`, `slot2_needs_rebase_reverify`, `runnable_work_available`, `stalled_worker`, `orchestration_resumed`, `queue_drained`, or `timeout` with `rearm_recommended`; while paused via `dev_orchestration_control.json`, sleeps silently with 0 git calls and wakes in `<=3s` upon resume)
- **Pause / Hard Stop (`Hard Freeze`) / Continue control (`orchestration_control.py` · `0600` `dev_orchestration_control.json`)**: `agy-queue pause [--hard] [--reason "..."]`, `agy-queue stop [--reason "..."]`, `agy-queue resume [--no-wake]`, `agy-queue status` (and `pr_remediator.py orchestration-{pause,stop,resume,status}`, `[P]`/`[S]` hotkeys in `agy-queue watch`, and `⏸ Pause Dev` / contextual `⏹ Hard Stop` (in `DRAINING` banner) / `▶ Continue Dev` in `[Dev Queue](sidecar://agy-dev-plugin/dev-queue-panel/)`). `Graceful Drain` allows ongoing active-lock tasks to finish cleanly while blocking new dispatches, disabling Chrome DevTools MCP (`pretool:paused-chrome-devtools`), silencing `watchdog.py`/`agy-doctor`, and suppressing `dev_ui_preview` staging & `restart_pro_api_server` restarts. `Hard Stop` (`mode="hard_stop"`, non-destructive Hard Freeze) additionally cuts off active dev workers/reviewers and `pr-worktree-*` tool calls immediately via `PreToolUse` (`pretool:hard-stop-active-workers`, leaving unrelated user chats unaffected), terminates active worktree subprocesses and preview dev servers (`stop_active_worktree_processes`), and blocks `--reuse-active`/`prepare-review`/`record-review` mutations while preserving all locks and worktrees until `Continue Dev` / `agy-queue resume`.
- **Self-diagnose workflow bottlenecks & 0-LLM PR compaction**: `pr_remediator.py queue-optimize --orchestrator-id <ORCH_CID> [--json] [--repos-dir <DIR>] [--stall-seconds <N>]` (detects `stalled_worker`, `phantom_pr_open`, `untracked_active_lock`, `priority_inversion`, `partial_wip_accumulation`, `parallel_lookahead_opportunity`, `stale_follower_needs_rebase`, `idle_orchestrator_with_runnable_work`, `pr_compaction_candidates`, `micro_pr_batch_candidates`, `repo_contention_hotspot`, `unanchored_pending_tasks`, `monolithic_god_files`, `missing_selective_test_runner`, `bloated_orchestrator_session`, `heavy_reviewer_overhead`, `missing_flash_routing`) + atomic `pr_remediator.py queue-compact [--apply] [--tier 1|all] [--repo SLUG] [--respect-pause] [--json]` (0-LLM Tier 1/2 Same-Repo, Partial-WIP & Split-Phase compaction with `0600` backup, live-lock/security/size/hub-file guardrails, `depends_on` rewiring, and 0-cycle/0-deadlock validation; CLI `agy-queue compact` & `[x]` Optimizer).
- **0-LLM Orchestrator Doctor, Safe Runtime Auto-Heal, Hybrid Wake-Up & Watchdog Sidecar (`agy-doctor` / `agy-queue doctor` / `pr_remediator.py queue-doctor`)**:
  - **Diagnose**: `agy-doctor [--json] [--sync-git]` inspects all slots (`Slot #1..#N`) including `AWAITING_AGENT_REVIEW`, `worker_cid` & `reviewer_subagent_id`, `dev_queue.json`, runnable repos, `queue-optimize`, live processes, wake logs (`wake_process_crash`), and tail transcripts (`server_restart_interrupted`, `idle_orchestrator_with_runnable_work`, `stalled_worker`, `missing_wait_for_unlock`, `phantom_pr_open`, `stale_follower_needs_rebase`, `standby_dependency_deadlock`, `quota_exhausted` 429).
  - **Safe runtime heal & quota-aware hybrid wake**: `agy-doctor --fix` reconciles locks, `phantom_pr_open`, 0-LLM `stale_follower_needs_rebase` (`rebase-reverify`), and `0600` `model_quota_cooldowns.json`; `agy-doctor --wake [--dry-run] [--force]` routes `--model=<fallback>` on `agentapi`/`agy` when unlimited/low-quota/429 fallback is active and suppresses wakes (`skipped_all_models_exhausted`) when all fallback pools are exhausted; `agy-doctor --heal` runs `--sync-git --fix --wake`.
  - **0-token health gate & daemon sidecar (`sidecars/dev-queue-watchdog/`)**: `agy-doctor --check-only [--json]` exits `0` when healthy and `2` when an anomaly requires `--fix` or `--wake` with 0 LLM tokens; `sidecars/dev-queue-watchdog/watchdog.py` (`sidecar.json`, `restart_policy: "always"`) polls `diagnose_orchestrator` every 5m (`--interval 300`) with 0 LLM tokens and triggers cooldown-gated `--fix`/`--wake` only on actionable anomalies.
- **Stamp active worker heartbeat**: `pr_remediator.py lock-heartbeat --workdir <WORKTREE_PATH> --worker-cid <WORKER_CID> --stage <LABEL>`
- **Reconcile merged `pr_open` items & prune stale compare `pr_urls`**: `pr_remediator.py queue-sync [--repo <owner/repo>] [--workdir <DIR>] [--fetch]` (also executed automatically during `lock-status --sync-git`)
- **Transition item state**: `pr_remediator.py queue-set-status --id <CID> --status <pending|in_progress|pr_open|merged|standby|hitl_blocked|cleaned|cancelled|rejected> [--importance TIER] [--component NAME] --branches ... --pr-urls ...` (automatically deduplicates `pr_urls` per `(repo_slug, branch_name)` keeping the richest verified URL: `/pull/` > rich verified `/compare/` > bare `?expand=1`)
- **Batch post-merge & scheduled NO_OP conversation cleanup**: `pr_remediator.py cleanup-merged-conversations --all-merged [--include-noop-actions --older-than-days 7] [--dry-run] --exclude-id <ORCH_CID>` safely sweeps Antigravity 2.0 SQLite `.db`/`.db-wal`/`.db-shm`, legacy `.pb`, `brain/<cid>`, `annotations/<cid>*`, and `presence/<cid>*` across Desktop (`~/.gemini/antigravity`) and CLI (`~/.gemini/antigravity-cli`) for `merged`, previously `cleaned` (leaked `.db`), and superseded-`cancelled` roots plus orphaned child subagents (discovered downward via `conversation_summaries.db` even when `brain/` is absent), while strictly protecting `CASCADE_RUN_STATUS_RUNNING` sessions, upward `parent_conversation_id` ancestors, active locks, and 8-char prefix matches against non-done synthetic queue items (`--dry-run` emits a full MB breakdown by artifact, runtime, and category)

## Orchestration Loop (`agy-dev-orchestrator` -> `agy-dev-planner` -> `agy-dev-executor`)
1. **Sync, Inspect Locks Per Repo & Run `queue-optimize`**: Run `lock-status --all --sync-git`, `queue-list`, and `queue-optimize --orchestrator-id <ORCH_CID>` at session start and after every merge wave. Recover any `stalled_worker`, resolve `priority_inversion` / `partial_wip_accumulation`, enforce proactive auto-handoff rotation at `100-110` steps (`bloated_orchestrator_session`, `AGY_DEV_MAX_ORCHESTRATOR_STEPS=100`, hard `110`, transferring active orchestrator ID via `queue-next --unlocked --orchestrator-id <NEW_CID>`), fast-forward merged local `main`, update `merged_repos` cleanly (only marking multi-repo items `merged` once all target repos merge), and deploy plugins via `git_client.py deploy-home`.
2. **Plan, Batch & Pre-Anchor (`agy-dev-planner`)**:
   - Locate exact files, line numbers, API contracts, cross-repo dependencies, and unit test targets upfront (pre-anchoring `unanchored_pending_tasks` during `pr_open` idle windows) before reserving a worktree.
   - Proactively batch small same-repo polish tasks (`micro_pr_batch_candidates`) and parallelize contract-first multi-repo work across unlocked repos.
   - If any target repository holds an active `dev_pr_lock`, immediately auto-enqueue as `pending` via `queue-add` with calibrated numeric priority and a concise visual queue confirmation table (never prompt for confirmation or priority).
   - Pass structured `anchored_context` to `agy-dev-executor` / `agy-code-developer` (skipping `agy-dev-planner` automatically when `queue-next --unlocked` returns `skip_planner_subagent: true`) using Flash control-plane orchestration (`AGY_DEV_ORCHESTRATOR_MODEL="gemini-flash-next"`), 0-LLM 3-tier risk effort (`micro`=`flash_lite`/`low`, `standard`=`Model="flash"` Round 1 + Round 2+ `Model="pro"` / `medium`, `critical`=`high`/`high`), compact CLI JSON default (`--verbose` opt-in), and Highest-Quota Cross-Family Balancing (`balanced_cross_family`) + preventive `<=25%` Eco / `429` fallback via `swarm models` & `pr_remediator.py quota-status` (see [`references/model-quota-fallback.md`](references/model-quota-fallback.md)).
   - **Mandatory Worker Watchdog Timer**: Immediately schedule a safety timer (`schedule` with `DurationSeconds=1200`, `TimerCondition=<worker_cid>`) on every background worker dispatch so silent worker stalls wake the orchestrator automatically.
3. **Execute Per-Repo Worktrees, Single-Pass Validation & Lean `PASS > 90` Review Loop (`agy-dev-executor`)**:
   - Work in isolated repo-scoped worktrees (`pr-worktree-<repo>-<branch>`), run single-pass `pr_remediator.py test-local --workdir <WORKTREE_PATH> --with-pre-commit` (executing `pre-commit` with `SKIP=unit-tests,qa-static-audit` then `qa_static_audit.py --incremental` + `selective_test_runner.py` once), and stage locally via `prepare-review` (`push-branch`) without pushing to `origin` yet.
   - Invoke `agy-code-pr-reviewer` (`Model="pro"`, Lean Reviewer Protocol: inspect `branch-diff` `verification_gate` first and skip redundant test/pre-commit reruns when `skip_redundant_test_rerun == true`). Only `record-review` with `verdict=PASS` and `score > 90/100` publishes `origin/<branch>`, transitions the queue item to `pr_open`, and exposes `manual_pr_url` (`ready_for_human_pr == true`) with **zero PR-ready emails** — PR readiness is surfaced exclusively via `agy-queue` TUI, `dev_queue_board.md`, `dev_queue.json`, and chat `manual_pr_url` (`--send-email` only dispatches Round-3 `[🟥]` KO circuit-breaker escalations). Orchestrators, executors, and reviewers MUST NEVER invoke `gmail_draft_client.py` or `AGY_DEV_NOTIFY_CMD` for PR readiness emails.
   - If `needs_reiteration == true`, automatically re-dispatch `agy-code-developer` with `developer_remediation_plan` and loop until `ready_for_human_pr == true` (max 3 rounds before circuit-breaking to `hitl_blocked` with zero PR links). Never surface PR URLs while locks are in `AWAITING_AGENT_REVIEW`, `NEEDS_REVISION_ITERATING`, or `ESCALATED_MAX_REVIEW_ITERATIONS`.
4. **Reactive Auto-Wakeup (`wait-for-unlock` + Safety Watchdog) & Clean Up**:
   - Whenever all target repos are busy/awaiting human PR merge and open queue work remains, launch `pr_remediator.py wait-for-unlock --orchestrator-id <ORCH_CID> --interval 15 --max-duration 3600` as a background `run_command` (`WaitMsBeforeAsync=500`) paired with a 65m safety watchdog `schedule` timer (`TimerCondition=<wait_task_id>`) so Antigravity's reactive task wakeup auto-resumes the orchestrator in `<15s` on merge/stall with **0 polling LLM tokens** (keeping `watch-pr-merge --daemon` for detached `main` fast-forward). Run `cleanup-merged-conversations --all-merged --exclude-id <ORCH_CID>` (or `--confirm-merged --id <CID>`) after merge verification.

## In-App `/hitl-review` Workflow (`hitl_blocked` -> `pending`)
Whenever the operator invokes `/hitl-review` (or asks to resolve `HITL_BLOCK` items inside Antigravity without manually hunting sidebar tabs):
1. **Enumerate Blocked Items**: Run `dev_queue_tui.py --status hitl_blocked --json` (or `pr_remediator.py queue-list`), sorted by ascending `priority`, resolving sidebar titles from `conversation_summaries.db`.
2. **Read Transcripts & Proposals**: For each `hitl_blocked` conversation ID, inspect its transcript via `dev_common.try_inspect_antigravity_conversation(<CID>)` (and any proposal `.md` artifacts under `$HOME/.gemini/antigravity/brain/<CID>/` or `$HOME/.gemini/antigravity-cli/brain/<CID>/`) to extract the blocking question, candidate options, recommended path, and impacted repositories.
3. **Collect Explicit Decisions via `ask_question`**: Present a crisp decision prompt for each blocked item (or compact batch when independent) via `ask_question` with concrete options (`Approve recommended`, alternative options, `Defer to standby`, `Reject`).
4. **Auto-Promote Queue State**:
   - On approval/choice: immediately promote `hitl_blocked -> pending` with the ratified decision recorded in notes:
     `pr_remediator.py queue-set-status --id <CID> --status pending --notes "HITL approved via /hitl-review: <decision>"`
   - On deferral or rejection: transition cleanly to `standby` or `rejected` with `--notes`.
5. **Re-Sync Board & Resume Queue**: Run `dev_queue_tui.py` (auto-syncing `dev_queue_board.md` if registered) and pick the next unblocked task via `pr_remediator.py queue-next --unlocked`.
