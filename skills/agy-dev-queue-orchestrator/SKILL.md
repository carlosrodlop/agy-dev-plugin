# Persistent Multi-Repo Dev Queue Orchestrator (`agy-dev-queue-orchestrator`)

Coordinates multiple pending engineering tasks across managed repositories without per-repo lock collisions—serializing edits within the same repository while allowing distinct unlocked repositories to progress in parallel.

## Persistent Queue Commands (`dev_queue.json` · `0600` + `file_lock`)
All operations run deterministically via [`pr_remediator.py`]($HOME/.gemini/config/plugins/agy-dev-plugin/skills/agy-code-remediation-pr/scripts/pr_remediator.py):
- **Inspect queue & active repo locks**: `pr_remediator.py lock-status --all --sync-git` and `pr_remediator.py queue-list`
- **Enqueue / update item**: `pr_remediator.py queue-add --id <CID> --title "..." --priority <10-90> --repos <repo1> <repo2> --status pending --target-files <f1> <f2> --depends-on <dep_cid> --rca-summary "..." --proposed-fix "..." --orchestrator-id <ORCH_CID>`
- **Locked-Repo Auto-Enqueue Policy (Zero Confirmation Prompt)**: When a **Design Contract** converges (or an approved task is ready) and one or more target repositories currently hold an active `dev_pr_lock`, **DO NOT ask the user for confirmation or priority** (never prompt *"Do you want me to enqueue this?"* or *"What priority should I assign?"*). Immediately inspect `dev_queue.json`, active `dev_pr_locks`, application architecture, dependencies (`depends_on`), and user urgency to assign a calibrated numeric priority automatically relative to existing queued tasks, execute `pr_remediator.py queue-add --status pending` immediately (including full `rca_summary`, `proposed_fix`, `target_files`, `depends_on`, and `repo_slugs` via `--repos`), and render a concise visual confirmation of the newly queued item and active queue state (compact Markdown table showing queue position, calibrated priority, target repo(s), active blocker lock, and next-up sequence).
- **Pick next unblocked items per repo (contract-first, 2-slot lookahead, transitive priority inheritance, 50% WIP-finish boost & partial-WIP cap)**: `pr_remediator.py queue-next --unlocked --orchestrator-id <ORCH_CID>` returns `next_unlocked_item` (`dispatch_repos` / `partial_multi_repo_dispatch` / `target_slot`), `slot2_candidates` (disjoint `NONE` / `TRANSITIVE` tasks eligible for `start-remediation --allow-slot2` via `analyze-overlap`), plus `runnable_by_repo` mapping every FREE repo to its highest-priority runnable task—computing cycle-safe transitive `effective_priority` (`inherited_priority_from` while preserving raw `priority`), subtracting `merged_repos`, boosting partially-merged items (`merged_repos` non-empty) ahead of 0% items on the same repo when `AGY_DEV_PRIORITIZE_PARTIAL_WIP=1` (default) while strictly preserving `P<=17` infrastructure precedence, and gating new 0% `partial_multi_repo_dispatch` when any downstream locked repo already has `>= AGY_DEV_MAX_PARTIAL_WIP` (`3` default) half-merged items waiting (keeping single-repo tasks and existing partial WIP unrestricted)
- **4-tier blast-radius overlap & post-merge follower rebase**: `pr_remediator.py analyze-overlap --repo <owner/repo> --workdir <DIR>` classifies candidate overlap (`NONE`/`TRANSITIVE` -> `--allow-slot2` + **Stacked Branches** `git rebase --onto` for `TRANSITIVE`; `INTERFACE_SHARED` -> Antigravity-native swarm `workspace='share'` in one shared worktree; `DEEP_SHARED` -> serialized execution with pipelined read-only `agy-dev-planner` pre-anchoring and dedicated per-feature test files `tests/test_<feature>.py`); `pr_remediator.py rebase-reverify --repo <owner/repo> --workdir <WORKTREE_PATH> --fetch` rebases promoted Slot #2 branches onto updated `origin/main` (`AUTO_PROMOTED_ZERO_LLM` / `NEEDS_AGENT_SEMANTIC_FIX` / `NEEDS_AGENT_CONFLICT_RESOLUTION`)
- **0-LLM reactive auto-wakeup waiter**: `pr_remediator.py wait-for-unlock --orchestrator-id <ORCH_CID> --interval 15 --max-duration 3600 [--stall-seconds 900]` (polls `sync_dev_pr_lock_with_git()` with 0 LLM tokens and exits cleanly on `repo_unlocked`, `slot2_needs_rebase_reverify`, `runnable_work_available`, `stalled_worker`, `queue_drained`, or `timeout` with `rearm_recommended`)
- **Self-diagnose workflow bottlenecks (0-LLM deterministic audit)**: `pr_remediator.py queue-optimize --orchestrator-id <ORCH_CID> [--json] [--repos-dir <DIR>] [--stall-seconds <N>]` (detects `stalled_worker`, `phantom_pr_open`, `untracked_active_lock`, `priority_inversion`, `partial_wip_accumulation`, `parallel_lookahead_opportunity`, `stale_follower_needs_rebase`, `idle_orchestrator_with_runnable_work`, `micro_pr_batch_candidates`, `repo_contention_hotspot`, `unanchored_pending_tasks`, `monolithic_god_files`, `missing_selective_test_runner`, and bounded telemetry anomalies: `bloated_orchestrator_session`, `heavy_reviewer_overhead`, `missing_flash_routing`)
- **0-LLM Orchestrator Doctor, Safe Runtime Auto-Heal, Hybrid Wake-Up & Watchdog Sidecar (`agy-doctor` / `agy-queue doctor` / `pr_remediator.py queue-doctor`)**:
  - **Diagnose**: `agy-doctor [--json] [--sync-git]` inspects per-repo locks, `dev_queue.json`, runnable unlocked repos, `queue-optimize`, live OS processes (`wait-for-unlock`, `watch-pr-merge` — stripping `-p`/`--prompt` payloads to avoid false positives), wake logs (`wake_process_crash`: `SIGABRT` / stdin metadata / non-zero exit), and tail-bounded transcripts across both Desktop (`$HOME/.gemini/antigravity/brain`) and CLI (`$HOME/.gemini/antigravity-cli/brain`) (`server_restart_interrupted`, `idle_orchestrator_with_runnable_work`, `stalled_worker`, `missing_wait_for_unlock`, `phantom_pr_open`)—plus prioritized PR-only orchestrator improvements (never auto-mutating tracked source files).
  - **Safe runtime heal & hybrid wake**: `agy-doctor --fix` reconciles locks & `phantom_pr_open` runtime state; `agy-doctor --wake [--dry-run] [--force] [--cooldown-seconds 900]` dispatches via `resolve_agentapi_cmd()` (`~/.gemini/antigravity/bin/agentapi` or `PATH` before `ANTIGRAVITY_AGENTAPI_EXE`, injecting `agentapi` as `argv[1]` for `language_server*` binaries) inside Antigravity Desktop/sidecars (`ANTIGRAVITY_LS_ADDRESS` set) or detached `agy --agent agy-dev-orchestrator --dangerously-skip-permissions -p "<diagnosis_prompt>"` from external terminals, probing startup exit status before persisting `0600` `agy_doctor_state.json` cooldown state; `agy-doctor --heal` runs `--sync-git --fix --wake`.
  - **0-token health gate & daemon sidecar (`sidecars/dev-queue-watchdog/`)**: `agy-doctor --check-only [--json]` exits `0` when healthy and `2` when an anomaly requires `--fix` or `--wake` with 0 LLM tokens; `sidecars/dev-queue-watchdog/watchdog.py` (`sidecar.json`, `restart_policy: "always"`) polls `diagnose_orchestrator` every 5m (`--interval 300`) with 0 LLM tokens and triggers cooldown-gated `--fix`/`--wake` only on actionable anomalies.
- **Stamp active worker heartbeat**: `pr_remediator.py lock-heartbeat --workdir <WORKTREE_PATH> --worker-cid <WORKER_CID> --stage <LABEL>`
- **Reconcile merged `pr_open` items & prune stale compare `pr_urls`**: `pr_remediator.py queue-sync [--repo <owner/repo>] [--workdir <DIR>] [--fetch]` (also executed automatically during `lock-status --sync-git`)
- **Transition item state**: `pr_remediator.py queue-set-status --id <CID> --status <pending|in_progress|pr_open|merged|standby|hitl_blocked|cleaned|cancelled|rejected> --branches ... --pr-urls ...` (automatically deduplicates `pr_urls` per `(repo_slug, branch_name)` keeping the richest verified URL: `/pull/` > rich verified `/compare/` > bare `?expand=1`)
- **Batch post-merge & scheduled NO_OP conversation cleanup**: `pr_remediator.py cleanup-merged-conversations --all-merged [--include-noop-actions --older-than-days 7] [--dry-run] --exclude-id <ORCH_CID>` safely sweeps Antigravity 2.0 SQLite `.db`/`.db-wal`/`.db-shm`, legacy `.pb`, `brain/<cid>`, `annotations/<cid>*`, and `presence/<cid>*` across Desktop (`~/.gemini/antigravity`) and CLI (`~/.gemini/antigravity-cli`) for `merged`, previously `cleaned` (leaked `.db`), and superseded-`cancelled` roots plus orphaned child subagents (discovered downward via `conversation_summaries.db` even when `brain/` is absent), while strictly protecting `CASCADE_RUN_STATUS_RUNNING` sessions, upward `parent_conversation_id` ancestors, active locks, and 8-char prefix matches against non-done synthetic queue items (`--dry-run` emits a full MB breakdown by artifact, runtime, and category)

## Orchestration Loop (`agy-dev-orchestrator` -> `agy-dev-planner` -> `agy-dev-executor`)
1. **Sync, Inspect Locks Per Repo & Run `queue-optimize`**: Run `lock-status --all --sync-git`, `queue-list`, and `queue-optimize --orchestrator-id <ORCH_CID>` at session start and after every merge wave. Recover any `stalled_worker`, resolve `priority_inversion` / `partial_wip_accumulation`, enforce mandatory session rotation at ~250–300 steps (`bloated_orchestrator_session`, transferring active orchestrator ID via `queue-next --unlocked --orchestrator-id <NEW_CID>`), fast-forward merged local `main`, update `merged_repos` cleanly (only marking multi-repo items `merged` once all target repos merge), and deploy plugins via `git_client.py deploy-home`.
2. **Plan, Batch & Pre-Anchor (`agy-dev-planner`)**:
   - Locate exact files, line numbers, API contracts, cross-repo dependencies, and unit test targets upfront (pre-anchoring `unanchored_pending_tasks` during `pr_open` idle windows) before reserving a worktree.
   - Proactively batch small same-repo polish tasks (`micro_pr_batch_candidates`) and parallelize contract-first multi-repo work across unlocked repos.
   - If any target repository holds an active `dev_pr_lock`, immediately auto-enqueue as `pending` via `queue-add` with calibrated numeric priority and a concise visual queue confirmation table (never prompt for confirmation or priority).
   - Pass structured `anchored_context` to `agy-dev-executor` / `agy-code-developer` using smart model routing (`Model="flash"` for focused pre-anchored tasks `<= 5` files, UI polish batches, and doc/config updates; `Model="pro"` for complex multi-file architecture refactors, and **always `pro`** for `agy-code-pr-reviewer`).
   - **Mandatory Worker Watchdog Timer**: Immediately schedule a safety timer (`schedule` with `DurationSeconds=1200`, `TimerCondition=<worker_cid>`) on every background worker dispatch so silent worker stalls wake the orchestrator automatically.
3. **Execute Per-Repo Worktrees, Single-Pass Validation & Lean `PASS > 90` Review Loop (`agy-dev-executor`)**:
   - Work in isolated repo-scoped worktrees (`pr-worktree-<repo>-<branch>`), run single-pass `pr_remediator.py test-local --workdir <WORKTREE_PATH> --with-pre-commit` (executing `pre-commit` with `SKIP=unit-tests,qa-static-audit` then `qa_static_audit.py --incremental` + `selective_test_runner.py` once), and stage locally via `prepare-review` (`push-branch`) without pushing to `origin` yet.
   - Invoke `agy-code-pr-reviewer` (`Model="pro"`, Lean Reviewer Protocol: inspect `branch-diff` `verification_gate` first and skip redundant test/pre-commit reruns when `skip_redundant_test_rerun == true`). Only `record-review` with `verdict=PASS` and `score > 90/100` publishes `origin/<branch>`, transitions the queue item to `pr_open`, and exposes `manual_pr_url` (`ready_for_human_pr == true`) with **zero PR-ready emails** — PR readiness is surfaced exclusively via `agy-queue` TUI, `dev_queue_board.md`, `dev_queue.json`, and chat `manual_pr_url` (`--send-email` only dispatches Round-3 `[🟥]` KO circuit-breaker escalations). Orchestrators, executors, and reviewers MUST NEVER invoke `gmail_draft_client.py` or `AGY_DEV_NOTIFY_CMD` for PR readiness emails.
   - If `needs_reiteration == true`, automatically re-dispatch `agy-code-developer` with `developer_remediation_plan` and loop until `ready_for_human_pr == true` (max 3 rounds before circuit-breaking to `hitl_blocked` with zero PR links). Never surface PR URLs while locks are in `AWAITING_AGENT_REVIEW`, `NEEDS_REVISION_ITERATING`, or `ESCALATED_MAX_REVIEW_ITERATIONS`.
4. **Reactive Auto-Wakeup (`wait-for-unlock` + Safety Watchdog) & Clean Up**:
   - Whenever all target repos are busy/awaiting human PR merge and open queue work remains, launch `pr_remediator.py wait-for-unlock --orchestrator-id <ORCH_CID> --interval 15 --max-duration 3600` as a background `run_command` (`WaitMsBeforeAsync=500`) paired with a 65m safety watchdog `schedule` timer (`TimerCondition=<wait_task_id>`) so Antigravity's reactive task wakeup auto-resumes the orchestrator in `<15s` on merge/stall with **0 polling LLM tokens** (keeping `watch-pr-merge --daemon` for detached `main` fast-forward). Run `cleanup-merged-conversations --all-merged --exclude-id <ORCH_CID>` (or `--confirm-merged --id <CID>`) after merge verification.

## In-App `/hitl-review` Workflow (`hitl_blocked` -> `pending`)
Whenever the operator invokes `/hitl-review` (or asks to resolve `HITL_BLOCK` items inside Antigravity without manually hunting sidebar tabs):
1. **Enumerate Blocked Items**: Run `dev_queue_tui.py --status hitl_blocked --json` (or `pr_remediator.py queue-list`), sorted by ascending `priority`, resolving sidebar titles from `conversation_summaries.db`.
2. **Read Transcripts & Proposals**: For each `hitl_blocked` conversation ID, inspect its transcript via `dev_common.try_inspect_antigravity_conversation(<CID>)` (and any proposal `.md` artifacts under `$HOME/.gemini/antigravity/brain/<CID>/` or `$HOME/.gemini/antigravity-cli/brain/<CID>/`) to extract the blocking question, candidate options, recommended path, and impacted repositories.
3. **Collect Explicit Decisions via `ask_question`**: Present a crisp decision prompt for each blocked item (or compact batch when independent) via `ask_question` with concrete options (`Approve recommended`, alternative options, `Defer to standby`, `Reject`).
4. **Auto-Promote Queue State**:
   - On approval/choice: immediately promote `hitl_blocked -> pending` with the ratified decision recorded in notes:
     `pr_remediator.py queue-set-status --id <CID> --status pending --notes "HITL approved via /hitl-review: <decision>"`
   - On deferral or rejection: transition cleanly to `standby` or `rejected` with `--notes`.
5. **Re-Sync Board & Resume Queue**: Run `dev_queue_tui.py` (auto-syncing `dev_queue_board.md` if registered) and pick the next unblocked task via `pr_remediator.py queue-next --unlocked`.
